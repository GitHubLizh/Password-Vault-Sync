# 手机可写（多设备同步修订件）

日期：2026-11-10　本文件是 [`docs/specs/2026-10-01-多设备同步.md`](2026-10-01-多设备同步.md) 的修订件：**不重写那份 spec，只记录"手机从只读变可写"带来的差异**；未提到的故事、接缝与决策一律以 2026-10-01 那份为准。决策链：[ADR 0024](../adr/0024-phone-writable-supersedes-0020.md)（取代 0020）、[0025](../adr/0025-worker-conditional-write-forwarding-amends-0012.md)（修订 0012，proposed）、[0026](../adr/0026-bucket-credentials-per-device.md)（关闭 7.3）、[0027](../adr/0027-trash-syncs-in-snapshot-purge-makes-tombstone.md)（补 0023 留白）。

## 1. 为什么修订

2026-11-10 用户重审同步需求，三问确认：使用者只有本人多台设备（不引入多人与账号体系）；"数据必须在自己磁盘、云端只见密文"原样成立（ADR 0008 不动）；第三方云可继续当载体（ADR 0012 不动）。唯一变化：**手机也要能写**。据此废弃 0020 的只读前提——这是一次拆墙（0020 整条、0012 一半），13 条其余决策原样成立，不是推倒重来。原方案未测先废的教训照 ADR 0022 的纪律延续：0012 与 0025 同为 proposed，阶段 0 实测闸门未过不上界面。

## 3. 新增与修订的故事

接缝代号沿用 2026-10-01 spec 第 5 节（A 进程内 HTTP、B 桌面 Playwright、C 纯函数、D 真桶脚本、E 手机端真浏览器）；E 自本件起扩义为"手机端含写路径"。

### 手机写路径（新增，接缝 E）

W1. 手机端新增条目：填表提交 → 页内以同步密钥重封**整份快照**（含新条目，0027 形状）→ 经 Worker 写转发条件 PUT（`If-Match` = 页内当前 ETag）→ 200 即"已同步"，页内快照与 ETag 一并更新。（E）
W2. PUT 得 412 → 拉云端 → 页内三方合流（基准 = 页内快照，接缝 C 同一份纯函数）→ 冲突条目逐条裁决（掩码默认、手动展开，规则同桌面）→ 裁完重试 PUT → 200。（E）
W3. 手机端编辑、删除条目与 W1 同语义；删除 = 移入回收站（0027），墓碑只在彻底删除或到期清除时产生。（E）
W4. 离线或 Worker 不可达时：写入口禁用并说明需要网络；表单内容仅存当前标签页内存，关页即丢，无草稿。（E）
W5. 手机端显示上次同步时间与可区分的失败原因（网络 / 鉴权 / 412 未裁完 / 云端异常）。（E）
W6. 拉到的密文解不开或格式非法 → 按 0017 异常族处理：停下并显示"云端快照异常，请在电脑上处理"，绝不静默、绝不当空库。（E）
W7. 密钥轮换后旧手机解不开新快照 → 引导重新配对（原故事 41），写能力随读能力一并失效。（E）
W8. 手机端不设 PIN / 口令门槛，信任边界 = 手机锁屏（0024）。（E）

### 既有故事的修订

R1（改故事 34）：手机粘贴配对码后即为该档同步组的**可写**成员；配对码本身不含任何写凭证，写能力来自 Worker 转发（0025），手机全程零桶凭证。
R2（改故事 39）：首次成功打开的声明改为"**这台手机解锁后，任何人打开本页面都能查看、修改、删除这个档的全部凭据**"；"清除本机存储"按钮照旧。
R3（改故事 31）：关掉同步 = 删四个 `.sync-*` 文件 + 删云端对象；"`vault.pvlt` 一个字节不动"的测试钉住不变。
R4（改故事 49）：磁盘契约从三文件变四文件；`.sync-token.enc` 是 v1 信封包裹的桶级 token，口令 = 本档主密码；`.sync-state.json` 仍用同步密钥加密。
R5：原故事 35（无写入口）、36（不缓存）、37（掩码）、38（清除存储）、40（看不到未配对档）中——36、37、38、40 原样成立；**35 作废**（手机有写路径了），其"任何写请求被代理侧拒绝"一句由 0025 的写转发端点取代，桌面浏览器与未配对网页仍无任何写路径。

### 桌面侧新增（接缝 A）

D1. 档设置里"开启同步"前要求粘贴桶级 API token（或沿用本机已粘贴的），落盘为 `.sync-token.enc`；配对码导入路径同样要求。（A）
D2. 改主密码的重包裹路径覆盖 `.sync-key.enc` 与 `.sync-token.enc` 两份，任一失败整体回滚、不留半态。（A）
D3. 删除 / 恢复 / 彻底删除 / 清空回收站按 0027 参与同步：移入与恢复是普通改动，彻底删除与到期清除产生墓碑；合流用例须覆盖"一边彻底删除、另一边恢复"的冲突分支。（A、C）

## 4. 阶段重排与闸门

| 阶段 | 交付物 | 闸门 |

## 5. 测试决策的差异

- **接缝 C 新增硬约束**：合流与云端小格式模块**不得引入 Node 专属 API**——同一份代码要在浏览器里跑（手机端页内合流）。这是对"纯函数模块"要求的收紧，落实为 CI 可查的形状（无 `node:` 导入、无 `fs`/`net`）。
- **接缝 E 扩义**：真浏览器真 fetch 覆盖 W1–W8，必含"412 → 裁决 → 重试 → 200"闭环、"离线写入口禁用"、"清除存储后重新配对"三组。
- **接缝 D 新增写转发实测步**：在真桶 + 已部署 Worker 上跑，结论进证据文件（含 binding `onlyIf` 支持 / 不支持的明文结论）。
- **接缝 A 的 fake transport** 增加"经代理写"复刻路径：`If-Match` 匹配 → 200 带新 ETag、不匹配 → 412、密文非法落库 → 拉取端解密失败，三条语义与真桶对齐。

## 6. 明确不做

先解除 2026-10-01 spec 第 6 节的一条旧禁令：**"不做手机写路径"**——被 ADR 0024 的需求变更推翻，是本轮唯一被解除的一条；其余旧禁令全部沿用。另加：

- 不做手机离线编辑、草稿持久化、PWA、后台自动同步（0024）
- 不做手机端 PIN / 口令门槛（首版；要加须另立 ADR）
- 不做手机端回收站界面（恢复与清空回桌面，0027）
- 不做手机端重锚定（0019 的重锚定只发生在桌面；手机遇云端异常只引导"回电脑处理"）
- 不做写端点鉴权（0025 已知限制：靠不可猜对象 key + 解密失败异常族兜底）
