# 多设备同步（multi-device sync）

> **修订（2026-11-10）**：手机端由只读改为可写。本文的手机相关内容（第 2 节"手机端是只读端"、故事 34/35/39、故事 31/49 的文件数、决策表第 2/14 行、阶段表的阶段 2、第 5 节接缝 E 的扩义、第 6 节"不做手机写路径"的解除、7.1 的三个文件、7.3 的待拍板项）以 [`2026-11-10-手机可写.md`](2026-11-10-手机可写.md) 与 ADR 0024–0027 为准；其余未提及部分继续有效。

## 1. 问题陈述

本仓库的定位是同步版（ADR 0007），但今天这台应用只会孤岛式地跑在一台机器上：服务只监听 `127.0.0.1:47821`，凭据加密在 `<存储目录>/<档>/vault.pvlt`，换机器只能手动迁移存储目录或导入加密备份（README 第 117 行原话就是这条限制）。用户在公司机和家里机之间靠"U 盘拷 `.pvlt`"来回倒，既容易倒出两个版本，也没有任何"哪份是新的"判据。

现有实现里有六处假设决定了这不是加一个按钮能解决的（行号均为 2026-10-01 实测核对）：

- **没有任何远端出口，也没有可注入的搬运口**。`buildApp` 的 `AppOptions` 只有 `directory / origin / staticDirectory / now / folderPicker` 五项（`server/app.ts:9-14`），`folderPicker?` 证明"外部能力靠注入参数进来"这个形状在本项目是可行的先例。
- **`VaultSnapshot` 的明文结构容不下同步元数据**。`snapshot()` 是白名单重建对象（`server/validation.ts:73`），未知顶层字段被**静默丢弃**——纯本地版和旧绿色包与本项目共用同一块磁盘、同一个 `vault.pvlt`，它们读一次再保存就会把新字段抹掉。因此同步状态绝不进 `VaultSnapshot`（ADR 0011 已记）。
- **磁盘上没有跨设备稳定的"同一个档"标识**。非默认档的身份就是目录名（`server/vault.ts:58-59`：`activeProfileId` 直接拼进路径），默认档则是 `null`（`:65`）。两台机器各自建过一个同名档，现有信息无法区分——这是 ADR 0010 的起因。
- **"当前档"只有解锁后才有**。`profiles()` 走 `readdir` + `isDirectory()` 扫描（`server/profile-store.ts:25-32`、`server/vault.ts:245`），新增的档内小文件不影响存在性判定，但**根目录新增文件必须是文件而不是目录**，否则会被当成一个档。
- **改主密码会重掷 salt 并整封重算**（`server/vault.ts:403`），而日常保存复用 `session.salt`（`:438-439`）；信封自描述且 salt 被绑进 AAD（`server/crypto.ts:63-71`）。"云端那份只认写它那一刻的口令"是既成事实，不是同步引入的——所以 ADR 0011 干脆把云端加密与主密码解耦。
- **那条 3 秒轮询与本功能无关**。`src/App.tsx:286-287` 打的是本机 `/api/status`（配合 `server/vault.ts:495` 的 `REVISION_CONFLICT` 防多标签页覆盖），`remoteChanged`（`src/App.tsx:541`）只反映本机变化。不许把它当"已经具备云端感知"，也不许复用同一条提示文案（ADR 0021）。

## 2. 方案概述

**每台设备继续各自持有一个本机服务和一份 `vault.pvlt`（事实源在本地）；云端只是一个对象存储桶里"每个档一个小 JSON 密文对象"的交换介质**（ADR 0008）。服务端在同步密钥的作用下把本地快照推上去、把云端快照拉下来，用**基准快照 + 本机 + 云端**三份做**条目级三方合流**（含删除集），冲突条目逐条交人裁决（ADR 0009、0018）。同步点挂在会话生命周期上：解锁拉、写后 debounce 推、界面一个手动按钮兜底，**不开面向云端的定时器**（ADR 0015），所以 `connect-src 'self'`（`server/app.ts:41`）与 `127.0.0.1` 监听一条都不用放宽——云端读写由 Node 侧发起，浏览器从不直接碰桶。

手机端是**只读端**：一个由几十行 Cloudflare Worker 同源 serve 的静态页，密钥来自配对码、存在浏览器存储里、不设口令门槛、不缓存任何快照（ADR 0012、0020）。

分三个阶段，阶段 0 是硬闸门（ADR 0022）：

| 阶段 | 交付物 | 闸门 |
|---|---|---|
| 0 实测骨架 | 不带界面的单档闭环脚本：真桶上跑完 推→改→拉→合流→旧 ETag `If-Match`→412→再推→200，并把 CORS 与手机蜂窝网可达性实测记录归档 | **三条外部事实任一不通 → 换载体重测，阶段 1/2 不得开工** |
| 1 桌面双向 | 逐档开启、配对、拉/推、合流与冲突裁决、同步状态可见、与改口令/恢复/删档/搬家交互 | 阶段 0 通过 |
| 2 只读端 | Worker + 手机页 | 阶段 0 的可达性实测通过且阶段 1 的云端格式定型 |

## 3. 用户故事

每条可独立验证。括号里是验证它的接缝（见第 5 节）。

### 阶段 0：载体实测闸门

1. 骨架脚本在真实桶上无人工干预地跑完：推一份合成快照（不含任何真实凭据）→ 改一条 → 拉 → 合流 → 用旧 ETag 发 `If-Match` 更新 **412** → 重新合流后再推 **200**。（D）
2. 实测记录（请求、响应码、ETag 值形态、耗时、region/endpoint）原文落到 `docs/specs/evidence/`，本 spec 的载体事实以那份记录为准，不以文档截图为准。（D）
3. ETag 的形态要实测确认是强 ETag 还是带引号/带分块后缀的形式，因为它是合流唯一的并发判据；结论写进证据文件。（D）
4. `SigV4` 签名在 Node 24 自带 `node:crypto` 里能自己完成，不引入第三方 SDK；结论与最小签名实现一起进证据文件。（D）
5. 手机在**关掉 WiFi、关闭任何代理**的蜂窝网络下跑 `scripts/carrier-reachability-probe.html`，结果原文进证据文件。**未通过前，阶段 1/2 的界面不得开始实现**；结果不支持 Cloudflare 时按 ADR 0012 换阿里云 OSS / 腾讯 COS，且那两家的条件写与 CORS 要重新实测。（人工 + D）
6. R2 是否支持对象版本控制要有明确结论（支持 / 不支持 / 仍未核实）写进证据文件；无论哪种都不改变 ADR 0017 的"云端不留历史"。（D）

### 开启与配对

7. 同步开关在**每个档自己的设置页**里。未开启的档：磁盘上不产生任何 `.sync-*` 文件，任何接口的响应里不含同步字段。（A）
8. 点击开启后，服务端为该档生成一个不可猜的同步标识和一个 32 字节随机同步密钥，写入档目录（`.sync-id`、`.sync-key.enc`、`.sync-state.json`），此时不产生任何云端对象。（A）
9. 首次同步 = 把当前本地库推上云端；对象不存在时用 `If-None-Match: *`，返回 412 说明云上已有同名步调的副本 → 转入"请用配对码接上"的引导，**不许覆盖**。（A）
10. 生成配对码：内容为只读代理地址 + 对象 key + 裸同步密钥；界面一次性显示，提供复制与二维码，本地不存档、界面不回显历史配对码。（A、B）
11. 第二台桌面设备粘贴配对码后：先验证对象可读且能用该密钥解密，再用本机这个档的主密码把密钥包裹存 `.sync-key.enc`，最后把拉到的快照写进同步状态当基准。本机若已有凭据，走合流而不是覆盖。（A）
12. 配对码缺字段 / 被截断 / 地址不可达 / 密钥解不开 → 各给一条可区分的错误并指出缺哪一段，绝不"猜默认值"或静默新建。（A）
13. 同步标识与同步密钥**逐档独立**：一个档泄露配对码不影响任何其他档；界面上不存在"一条码连所有档"的入口。（A）

### 拉与推

14. 解锁成功或切换身份档后自动拉一次；云端与基准一致时不产生任何界面变化。（A、B）
15. 云端比基准新而本机没有改动 → 用云端替换本机库并更新基准与 ETag，界面给一条"已同步"提示。（A）
16. 每条保存、删除、改设置成功后 debounce 推一次；推成功则基准快照、ETag、待同步计数一起更新。（A）
17. 界面上没有面向云端的定时器：本功能的 Playwright 用例断言在用户不操作的时间窗内不出现任何外部 HTTP 请求，且 `src/App.tsx` 那条 3 秒轮询的目标仍是 `/api/status`。（B）
18. debounce 未落地时用户手动锁定：提示"还有 N 条未同步，仍要锁定？"，确认后允许锁定并**保留待同步状态**（锁定不丢改动）。建议 debounce 值 2 秒，最终值待定（见 7.4）。（A、B）

### 合流与冲突条目

19. 三方比较的输入是基准快照、本机快照、云端快照各自的**条目集 + 删除集**。只有一边改过的条目自动合并。（C）
20. 一边删除而另一边从未改过它 → 删除生效，合流结果里本机与云端都不再有该条。（C）
21. 一边删除而另一边改过它 → 判为**冲突条目**，界面逐条列出，只两个选项："确认删除" / "保留对方的修改"。（A、B、C）
22. 两边都改过同一条 → 冲突条目，逐条"用本机 / 用云端"整条取舍，不做字段级拼接。（B）
23. 冲突条目未全部裁决完之前，不得推送；界面给出"还剩 N 条未裁决"。（A）
24. 两边各自新建的条目一律并存（id 是服务端生成的 UUID，`server/validation.ts:75` 起那套正则保证不撞号）；本期不做重复检测。（C）
25. 合流结果只递增 `revision`，不改变任何条目的 `id`、`createdAt`。（C）
26. 冲突裁决界面显示两边的名称 / 用户名 / 地址 / `updatedAt`，**密码与备注默认掩码**，逐条手动展开。（B）

### 与既有功能的交互

27. 改主密码：本地信封按现有逻辑重算（`server/vault.ts:379-417`），`.sync-key.enc` 用**新**主密码重新包裹，同步密钥不变、云端一字节不动。重包裹失败必须整体失败并回滚，不许出现"新口令解不开旧包裹"的半态。（A）
28. 从加密备份恢复成功后**强制进入重新锚定**：以本机这份全量替换云端，或丢弃刚恢复的内容改从云端拉；两个分支都重写基准与 ETag（ADR 0019）。恢复本身的覆盖语义零改动，`tests/api.test.ts:448` 那条断言不许动。（A、B）
29. 重新锚定中途关闭页面 → 下次进入同步页时强制先处理这个未决态，不许留成静默分叉。（A）
30. 删除身份档时默认连云端对象一起删，删前提示先导出备份；本地 `before-delete-*.pvlt` 现有行为不变。（A）
31. 关掉某档的同步：删除三个 `.sync-*` 文件 + 删除云端对象，本地 `vault.pvlt` 一个字节不动。这条必须被测试钉住。（A）
32. 整栋搬家（`/api/storage-location`）把三个同步文件随目录树一起迁移，同步关系不断；旧目录那份历史副本里也带着标识文件，不得因此判重或串档。（A）
33. 存储哨兵判据不变：仍是"这棵树里至少还有一个 `vault.pvlt`"（`server/storage-location.ts:52`、`:77`），同步文件不参与存在性判定。（A）

### 只读端（阶段 2）

34. 手机浏览器打开配对码里的地址并粘贴配对码后，密钥与对象地址存入该浏览器存储；页面**不需要任何口令**即可展示当前档条目。（E）
35. 只读端没有写路径：页面上没有写入口，且任何写请求被代理侧拒绝。（E）
36. 不缓存云端密文与明文；每次打开重新取；明文只存在于当前标签页内存。（E）
37. 秘密字段默认掩码，与桌面"默认隐藏秘密"一致。（E）
38. 页面提供"清除本机存储"，点完立即失效；重新查看必须重新粘贴配对码。（E）
39. 首次成功打开时页面必须写明：**这台手机解锁后，任何人打开本页面都能看到这个档的全部凭据**。不许写成"端到端加密所以安全"。（E）
40. 只读端看不到任何未与之配对的档——连名字和数量都没有（ADR 0016 的直接后果）。（E）
41. 桌面轮换同步密钥后，旧只读端解不开新快照 → 显示"本档同步密钥已更换，请在电脑上重新获取配对码"，不显示任何残留条目。（E）

### 失败与可见状态

42. 本地保存永不因同步失败而失败：`persist`（`server/vault.ts:438-439`）不在同步的失败路径上，同步是它之后的一步。（A）
43. 有未推送改动或上次同步失败时，界面常驻显示"待同步 N 条 · 上次同步于 …"，失败原因可展开。（B）
44. 云端返回 **404** 或对象凭空消失 → 报"云端同步副本不存在"并要求人工确认才允许重建，**绝不静默当成空库**后把本机全量推上去（ADR 0017）。（A）
45. `412` 不算失败：拉云端 → 合流 → 再推；用户视角的结局只有"已同步"或"有 N 条冲突待裁决"。（A）
46. 凭证失效、网络不通、超时三类失败有可区分的 `code` 与文案，且三条都不阻塞本地使用。（A）
47. 云端同步状态与本机 `remoteChanged` 提示（`src/App.tsx:541`、`:577-578`）文案上严格分开，不许合并成一句"检测到新版本"。（B）
48. 服务重启后待同步计数与基准仍在（它们来自 `.sync-state.json`）。（A）

### 安全边界与磁盘契约

49. 磁盘上三个新文件都不含明文凭据：`.sync-key.enc` 是现有 v1 信封包裹的 32 字节，`.sync-state.json` 里的基准快照与删除集用**同步密钥**加密后存放。（A）
50. `vault.pvlt` 的格式与判别符 `'local-password-vault'`（`server/crypto.ts:10`）、数据目录 `%LOCALAPPDATA%\PasswordVault`、导出备份文件名前缀、既有界面文案——四个契约名零改动（ADR 0007）。（A）
51. 云端小格式有独立解析器与独立判别符，**不复用 `parseEnvelope`、不放宽它的白名单**（`server/crypto.ts:31-52`）。（C）
52. 云端对象 key 只含同步标识，不含档名；服务端日志、错误信息、测试输出里都不出现明文条目、密钥、令牌或密文全文。（A）
53. 8 MiB 与 10000 条上限沿用（`server/crypto.ts:6`、`server/validation.ts:75`）；超出时同步报"库已达上限"，本地保存仍照常成功。（A、C）

## 5. 测试决策

## 7. 补充说明（给实现者的坑位提示）

### 7.1 档目录里的三个新文件

`.sync-id`（同步标识，明文，不是密钥）、`.sync-key.enc`（现有 v1 信封，明文=32 字节同步密钥，口令=本档主密码）、`.sync-state.json`（基准快照 + 基准 ETag + 删除集 + 待同步计数 + 上次同步结果，**内容用同步密钥加密**）。三条纪律：① 都是**文件**，根目录那份不能被 `readdir` 的 `isDirectory()` 认成一个档；② 都不参与存在性哨兵；③ 基准快照绝不能明文落盘——它含全部凭据，明文写出等于把"盘上只有密文"这条信任前提当场作废。

### 7.2 云端对象草案

key：`password-vault-sync/<同步标识>.json`（不含档名）。body 判别符与 v1 信封不同（建议 `format: 'password-vault-sync'`），字段大致 `{ format, version: 1, cipher: 'aes-256-gcm', iv, tag, ciphertext, syncId, revision, updatedAt, deleted: [{id, at}] }`，密钥 = `HKDF(同步密钥, info=同步标识)`。**并发判据是 ETag，不写进 body**（写时 `If-Match: <基准 ETag>`，读时把响应 ETag 记进基准）。上限沿用 8 MiB；`deleted` 数组要有显式长度上限并在超限时给出可操作提示，否则它会无感增长。

### 7.3 待拍板（本 spec 唯一悬着的实现前提）

配对码按 ADR 0014 只携带"只读代理地址 + 对象 key + 同步密钥"，**不含桶的写凭证**。因此第二台桌面要能写，必须另有凭证。建议：**每台桌面各自在设置里粘贴一把自己的桶级 API token**（好处是能按设备单独吊销、配对码不承担写权限扩散），token 落盘沿用 `.sync-key.enc` 的思路包一层口令加密。此路等于 ADR 0014 的一处补缝，需要用户拍板后再补一条 ADR；在此之前不得把它当已定事项写进实现。

### 7.4 未决项（留给实现或后续 ADR，不许在代码里偷偷定案）

墓碑保留多久（永久最准但快照无上限增长）、重复条目的检测与提示、debounce 的具体毫秒数与锁定瞬间的收尾、对象存储的请求/存储配额与成本上限估算、`If-Match` 与分块上传/多部分上传的交互、以及"云端对象被人工在控制台删掉"之外的人为破坏场景的容错边界。

### 7.5 手机页传密钥的方式

配对码里的裸密钥若走 URL query，会进 Worker 的访问日志与 Referer。实现时应走 **URL fragment**（`#` 之后，浏览器不发给服务器）+ 只读端本地存储；这一条属于 ADR 0014"渠道风险"的最小缓解，不改决策只改泄漏面。
