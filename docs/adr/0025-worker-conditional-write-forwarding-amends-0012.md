# 只读代理 Worker 增加条件写转发，修订 ADR 0012

> 状态（2026-11-10）：修订 [ADR 0012](0012-carrier-object-storage-plus-readonly-worker.md) 的"Worker 只做两件事、不持写权限"结论；0012 的其余结论（同源 serve、不设 ACAO、不解密、不存配对状态）继续有效。与 0012 同为 proposed，待阶段 0 实测（含本条新增的写转发实测项）。

2026-11-10 决定：Worker 增加一个**写转发端点**——手机端把整份重封后的云端快照密文连同基准 ETag 发给它，Worker 以 `If-Match` 条件 PUT 写入 R2，把 412/200 原样回传；自己不解密、不校验内容、不存任何状态。桌面端写路径不变（Node 侧 SigV4 直发对象存储）。动机来自 ADR 0024：手机可写之后，"怎么写"只剩两条路，本条选了不开新洞的那条。

选 Worker 转发而不是手机直发桶，是因为后者要同时开三个洞：浏览器里自签 SigV4、桶开 CORS、长期凭证进浏览器存储。要如实记账的代价是 0012 对 0008 的折扣变大——Worker 从"搬运密文"变成"搬运密文并持写权限"。但**机密性没有变差**：Worker 本来就 serve 手机页的 JS，被换包的 Worker 一直都能从浏览器存储读走同步密钥（0020 已记录这一点），而它至今解不开密文。变差的只有**完整性**——恶意 Worker 可以写垃圾或删对象。关键在于这个完整性风险是 0024（手机可写）固有的、不是本条引入的：只要手机页由 Worker serve，"页面代码可信"就等于"Worker 可信"，换任何写路径都躲不掉；本条只是把已有的信任如实入账。

转发实现有两条候选路，取舍是阶段 0 闸门的新增实测项：① R2 binding 的 `put()` 若支持 `onlyIf` 条件写，凭证就是 binding 本身，Worker 里零 AK/SK；② 否则 Worker 用 WebCrypto 自签 SigV4 子请求打 S3 API，凭证是一把存为 Cloudflare secret 的 AK/SK。被否决的另外三条：手机直发桶（0024 已记）；Worker 发预签名 URL 给手机（0012 已否——SigV4 预签名最长 7 天且本质是 bearer token）；Worker 做服务端合流或内容校验（0008 否决整个类别，本条维持"转发不透明字节"）。另否决"写经某台在线桌面中继"：桌面不常开，且引入"哪台是宿主"的拓扑依赖。

## 后果

- **写端点无法鉴权，如实记为已知限制**：Worker 不持同步密钥（0014 的"不存配对状态"延续），无法验证来者是否同组成员。实际闸门是同步标识不可猜（0010）加上同步密钥解不开垃圾密文；"拉到解不开或格式非法的云端快照"并入 0017 的异常族（与 404 同级：停下问人，绝不静默重建、绝不当空库）。
- **412 在转发层 1:1 保留**：转发不许把 412 吞成 200 或 500——它是 0009 合流安全的唯一并发判据，吞掉等于并发写失去判据。
- **`worker/index.mjs` 的 405 只读拒绝要改**：现有骨架对非 GET/HEAD 一律 405（`worker/index.mjs:20-22`），写转发的 PUT 路由是它唯一的例外；CSP 头与 `cache-control: no-store` 不变。
- **Worker 从几十行长成真实组件**：路由、凭证、错误透传都要按"要维护的代码"对待；`worker/wrangler.toml:9-11` 注释掉的 R2 binding 届时解注释（走①）或改用 secret（走②）。
- **阶段 0 闸门从三条外部事实变四条**：条件写、CORS、蜂窝网可达性之外，新增"已部署 Worker 上跑通 PUT 带 `If-Match` → 412/200 的转发闭环"，并把①与②的取舍结论写进证据文件。
