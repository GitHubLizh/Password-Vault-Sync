# 手机端成为同步组的可写成员，取代只读端

> 状态（2026-11-10）：取代 [ADR 0020](0020-read-only-phone-no-passphrase.md) 的"手机只读"前提；与只读无关的结论（不设口令、不缓存、明文只在标签页内存、清除本机存储）被本条原样继承，0020 正文留着当历史。

2026-11-10 决定：手机端从"打开就能看"的只读端升级为同步组的**完整可写成员**——在手机上新增、编辑、删除条目并推送到云端对象，与桌面端同一套合流规则（ADR 0009、0018）、同一个并发判据（`If-Match` 条件写）。触发点是用户重审需求后的"三不变一变"：使用者仍只有本人多台设备（不引入多人与账号）、数据必须在自己磁盘且云端只见密文（0008 原样）、第三方云可继续当载体（0012 原样），唯一变化是**手机要能写**。据此废弃 0020 的只读前提——这是一次拆墙，不是整套同步设计推倒重来。

技术前提是被 ADR 0013 白送的：云端小格式就是 HKDF + AES-GCM，WebCrypto 原生既能解也能封，手机写不需要任何新密码学。被否决的三条：① 维持只读、要改回电脑做（被需求直接否决）；② 手机装完整本机服务或 PWA 养一份本地库（离线能力最强，但"云端只是交换介质"变成"手机也是事实源"，换机时多一份要迁移的密文库，且 PWA 后台同步在 iOS 与国产安卓上死状百出）；③ 手机直发对象存储（浏览器里做 SigV4、桶开 CORS、长期凭证进浏览器存储，三条全是新增攻击面与实测项——由 ADR 0025 的 Worker 写转发替代）。

## 后果

- **免口令的爆炸半径如实放大**：解锁的手机从"能看全部凭据"变成"能看、能改、能删"。云端不留历史（0017），手机端的破坏性写会广播到同步组全部设备，唯一的后悔药仍是桌面侧的本地导出备份。0020 那句信任边界声明改写为"能查看、修改、删除"，且"不许包装成端到端加密所以安全"的纪律照旧。
- **写是直通的，没有本地草稿**：每次写都是"取当前快照 → 页内改 → 整份重封 → 条件 PUT"；关掉页面，未提交的表单内容即丢。离线时写入口禁用——云端是手机唯一的数据来源，0008 里"事实源在本地对手机不成立"的例外原样延续。离线编辑与草稿持久化都不做。
- **手机参与合流但不需要持久基准快照**：三方比较的"基准"就是本页最近一次取到并解开的那份，只活在标签页内存里，与 0020 的"不落任何持久副本"不冲突。412 时在页内完成拉-合-重试，冲突条目在手机上逐条裁决，规则与桌面一字不差。
- **不设 PIN 门槛（首版）**：手机锁屏就是那个门槛，与 0020 否决口令门槛的论证同构——为一个假门槛引入 PBKDF2 弱 KDF 不划算。将来要加须另立 ADR，不许在代码里悄悄加。
- **同步时机的手机版**：拉 = 打开页面与每次写后；推 = 写直通本身；兜底 = 重新打开页面。不开任何后台同步——0015 的"生命周期驱动"在手机上更彻底：页面死了就没有同步。
