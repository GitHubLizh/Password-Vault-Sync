# 同步逐档显式开启，未开启的档不落任何同步标识

> 勘误（2026-11-10）："关掉同步删掉两个标识文件"应为"三个同步文件"（`.sync-id` / `.sync-key.enc` / `.sync-state.json`）；自 [ADR 0026](0026-bucket-credentials-per-device.md) 起为四个（另有 `.sync-token.enc`）。

2026-10-01 定：同步开关在**每个身份档自己的设置里**。没开启的档不生成 `.sync-id`、不生成密钥包裹文件、不产生任何云端对象；开启的那一刻才生成这两个标识。

否决的三条：① 全局一键把所有档接上——要么出现"一把密钥管所有档"，正面推翻 ADR 0010 的档级对象与 ADR 0011 的"同步密钥作用域是单档"；要么背后还是生成多条码只是拼成一堆，省事是假象。② 新档默认自动参与、可逐档关——体验无缝，但用户为"这次用完就删"建的临时档会被静默推上云，而密码库里"默认不外流"应当是默认值。③ 建档时就先生成标识、上传与否再说——那会造出"有标识但从未同步"的第三种状态，界面上要多解释一个用户根本不关心的概念。

## 后果

- **与"解锁一个档看不见其他档"的原则一致**：一个档的密钥泄露或配对码外流，不影响其他任何档。
- **配对码是档级的**（ADR 0014 已定，本条把它坐实）：三个档都要同步就是三次开启、三条配对码，不许图省事合并。
- **未开启的档在别的设备上就是不存在**：不产生"这台机器上有个档你没同步"的提示，也不许为了提示而去读未开启档的任何内容。
- **开启是幂等且可回退的**：关掉同步删掉两个标识文件即可，本地 `vault.pvlt` 一个字节不动——这条要能被测试钉住。
