# 云端只保留一份当前快照，不留任何历史版本

2026-10-01 定：云端对象**永远只有当前那一份**，覆写即历史消失；不引入平台版本控制，也不在应用里写时间戳副本。关掉某档的同步、或删除该档时，**默认连同云端对象一起删除**，删除前先提醒用户导出本地加密备份。云端返回 404 或对象凭空消失，一律当**异常**报告并要求人工确认才允许重建，**绝不静默当成"云端是空库"**后把本机全量推上去。

理由里最硬的一条是密码库特有的：同步密钥不会随条目删除而改变，所以**云端每多一份历史密文，就是"已删除凭据"多一份可被同一把密钥解开的尸体**。平台 versioning 或应用层历史副本都能当后悔药，但那颗药是用泄露面换的。

需要点明的核实缺口：**R2 是否支持对象版本控制，我没能从 Cloudflare 官方文档核实到结论**（两个常见文档路径返回 404，站内搜索无结果）。本条不依赖它，但若日后要改主意开 versioning，必须先实测。

## 后果

- **后悔药不在云上**：合流判错、误删条目，能救回来的只有本地导出备份（`/api/backup`）和本机的基准快照。文档不许写"云端有版本历史可随时回滚"。
- **`If-Match` 的 412 是唯一的并发判据**：不留历史意味着"覆盖错了"无法靠平台回退，所以 ADR 0009 的合流与条件写不是可省的实现细节，而是数据安全本身。
- **404 与"空库"必须区分**：空库是"这个档没有任何条目"，404 是"云端同步关系不存在了"。前者可以正常同步，后者必须停下问人——否则一次误删就变成了"本机全量覆盖"。
