# 云端快照用独立的小格式，不复用 `vault.pvlt` 的信封 v1

2026-10-01 定：云端对象是**它自己的格式**——AES-256-GCM，密钥 = HKDF(同步密钥)，不含 KDF 参数、不含 salt 概念、`format` 判别符与本地信封不同。本地的 `vault.pvlt` 与导出备份继续是严格的信封 v1（`server/crypto.ts:9-18`），**两者不是同一个格式，也不许互相冒充**。

理由：`parseEnvelope` 用 `format === 'local-password-vault' && version === 1 && kdf N=131072/r=8/p=1` 硬白名单（`server/crypto.ts:36-39`），而 scrypt 在浏览器里根本没有原生实现——WebCrypto 只有 PBKDF2/HKDF/AES-GCM 那一族。若云端沿用 v1，手机只读页要么塞一个 scrypt WASM（N=131072、r=8 意味着 131072×8×128 B = **128 MiB** 内存，低端安卓是真实翻车点），要么手机功能作废。换成 HKDF + AES-GCM 后手机页用浏览器内置能力就能解密。

否决的备选：① 云端就是 v1 信封原样字节（"云端=本地那份文件的副本"心智最简，但手机端背 WASM，且 `changeMasterPassword` 新掷 salt 后每次改口令都要全量重传）；② 云端用 PBKDF2 派生以保持"两边都是口令派生"的形式一致——PBKDF2 在 GPU 上远比 scrypt 便宜，用更弱的 KDF 换来一个好看的形式，收益小于代价；③ 手机不解密只做入口提示，等于把"手机只读"作废。

## 后果

- **磁盘契约不受影响**：`'local-password-vault'` 判别符仍是 ADR 0007 列名的"不许跟着仓库定位改"的四个名字之一，本条不碰它，也不新增版本号。
- **两个格式两套校验**：云端小格式的解析器要独立存在（同样严格白名单），不许复用 `parseEnvelope` 然后靠参数分支——那会把 v1 的白名单撑开，正是 ADR 0001 要避免的事。
- **云端不是备份**：用户手里那份 `.pvlt` 加密备份仍能独立恢复；云端对象丢了，本地库和导出备份都不受影响。文档里不许把云端快照写成"你的备份在云上"。
