# 多设备同步回到本仓库范围，两条产品线按仓库分工

2026-10-01 决定：撤销 ADR 0006 的范围收敛。本仓库（`Password-Vault-Sync`）定位为**同步版**——在这份本地保存之上增加多设备数据同步；只做单机的**纯本地版**继续由 `Password-Vault` 仓库独立维护、独立发版。两条线功能定位不同，不是新旧关系，也不是"迁移与被迁空的关系"，仓库名前缀相同只说明同源。

需要说清楚的前提：本决定只改变**范围归属**，不带来任何代码。09-30 按 ADR 0006 删掉的同步接缝（`server/sync/provider.ts`、`shared/merge.ts` 及其测试）不会因为这条 ADR 自动回来，同步方案仍是零——`docs/specs/2026-09-29-多设备同步.md` 与旧 ADR 0002–0004 已删且没有从历史取回，坚果云 WebDAV 浏览器直连实测 401、条件写没有证据，provider 选型未定。重新起步要先出 spec 和 ADR，不在实现里塞进不去的接口。

## 后果

- **README 的边界声明改口**：第 3 行的"没有云同步"和第 119 行"不做跨设备同步——这是设计边界而非待补功能"不再成立，同步是本项目待建的目标能力。在它落地之前，本仓库的行为与纯本地版一致，换机器仍靠手动迁移存储目录或导入加密备份，这一点不能对外含糊。
- **ADR 0006 顶部标注被本条取代**，正文原样留着（它记录的删除动作和当天事实成立）。0002–0004 的空号不重排的约定不变，所以本条继续往后编为 0007。
- **两仓库共享到 `3861667` 的历史**：`v0.1.0 / v0.1.1 / v0.1.2` 三个 tag 在两个仓库指向同一批提交。搬运当天把纯本地版的附件按字节复制过来核对过 sha256（v0.1.1 `bdb7dd82…` 40,589,761 B、v0.1.2 `065c75d5…` 39,070,305 B，v0.1.0 本来就没附件），随后按下一条决定撤销——复制这件事只用来证明 tag 指向的内容两边同源，不代表本仓库要长期分发它们。
- **分发名换为 `PasswordVaultSync`（2026-10-01 定）**：本仓库首个同步版本的用户可见产物改名——压缩包与解压后的顶层目录由 `PasswordVault` 换成 `PasswordVaultSync`，附件即 `PasswordVaultSync-win-x64.zip`，与纯本地版彻底区分。**触发点是同步功能开发完毕、真要发第一个包那天，不是现在**：同步可用之前本仓库发不出名实相符的包，提前改只会让两个名字并存更久。落地时要一起改的地方：`scripts/package.mjs` 的 `packageName`、`scripts/precheck-release.mjs` 的 `stage` 与 `zipFile`、`tests/package.spec.ts` 的 `packageRoot`、README 第 33 行与第 53 行的包目录树，以及包内 `使用说明.txt` 的生成文案。
- **v0.1.x 在本仓库只留 tag，Release 撤销（2026-10-01 定并执行）**：那三个附件是纯本地版的构建物，同步版仓库不分发"没有同步的包"。三条 Release 已由用户删除，实测 `gh release list` 为空、三个 tag 仍在（`045d0f1 / 8e2374c / dfb70e3`）、`releases/latest/download/PasswordVault-win-x64.zip` 返回 404；纯本地版仓库那边三条 Release 与 200 直链原样不动。所以本仓库现在**没有对外下载渠道**，要拿 v0.1.x 安装包只能去纯本地版仓库，README 不许再放指向本仓库的下载直链。tag 留着是为了锚住共同历史和将来的版本序号，`npm run precheck` 仍会因"标签 v0.1.2 已存在"拒绝发版，这是正确的闸门。
- **四个名字不许跟着定位改**：`server/crypto.ts` 里的信封判别符 `'local-password-vault'`（磁盘格式 v1 契约，被 `parseEnvelope` 白名单钉住，见 ADR 0001）、数据目录 `%LOCALAPPDATA%\PasswordVault`（一改，老用户的 `vault.pvlt` 就地失踪）、导出备份的文件名前缀 `local-password-vault`（`src/App.tsx:392`，用户手里已经有这类 `.pvlt`）、以及界面文案。`package.json` 的 `name` 改为 `password-vault-sync` 只是 npm 标识（`private: true`，没有任何脚本读它），**不与上面任何一条联动**——尤其不要"顺手对齐"把 crypto 的 `format` 一起改掉。
- **本地那个从未发布过的包不算数**：`release/PasswordVault-win-x64.zip`（39,068,853 B / sha256 `d159ee21…`，09-30 01:54）与线上 v0.1.2 附件（39,070,305 B / `065c75d5…`）不是同一个包。按 ADR 0005"不为字节漂移重发已发布的包"，它不能替换 v0.1.2，只能随新版本自然对齐；`npm run precheck` 也会因"标签 v0.1.2 已存在"拒绝，这是正确的闸门。
