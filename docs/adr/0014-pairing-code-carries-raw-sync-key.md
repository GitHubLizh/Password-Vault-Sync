# 配对码直接携带裸同步密钥，服务端不存配对状态

2026-10-01 定：新设备（第二台电脑、手机只读端）加入同一个档的同步组，靠桌面端生成的一条**配对码**：内含只读代理地址、对象位置（由 `.sync-id` 派生，ADR 0010）与**裸同步密钥**。新设备收下后立即用本档主密码包裹存盘（ADR 0011），界面上不再回显裸值。

否决的三条：① 一次性兑换票据（密钥加密副本临时放 Worker/KV，24 小时失效）——渠道里不含密钥确实更安全，但它把 Worker 从"转发 GET + serve 静态页"变成要存状态、要清理、要有过期语义的服务，正面撞上 ADR 0012 的"Worker 只做两件事"；② 手工填三个字段（代理地址 / syncId / 密钥 base64）——最透明，但对"解压即用"的非技术用户基本不可用，错一位就是解不开；③ 不做配对、每台设备各生成各的密钥、跨机靠现有加密备份——那等于放弃多设备，与 ADR 0007 的仓库定位冲突。

## 后果

- **要如实写进已知限制**：密钥在剪贴板 / 二维码 / 那条 URL 里以明文存在过，传输渠道（微信、网盘、邮件）会把它的留存时间变成别人的掌控范围。这不是"绝对零知识"，文档不许把它写成零风险。
- **必须提供密钥轮换入口**：轮换 = 生成新同步密钥 → 用它重写云端那一份 → 旧设备靠新配对码重新接上。**旧设备不会被自动踢掉**，除非轮换后云端被重写且旧密钥失效——这是轮换的主要用途，也是"手机丢了"的唯一应对手段，要在界面里说明白。
- **配对码是档级的**：一个档一条码，多个档就是多条码。不许出现"一条码连所有档"的省事实现，那会让 ADR 0010 的档级隔离失去意义。
