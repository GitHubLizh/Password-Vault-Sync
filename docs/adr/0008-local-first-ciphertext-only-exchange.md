# 同步采用本地优先：每台设备各跑本机服务，云端只存密文快照

2026-10-01 定：多设备同步的顶层形态是**每台设备继续拥有自己的本机服务和自己的 `vault.pvlt`（事实源在本地），云端只充当一份密文快照的交换介质**。被否决的三个备选：① 中心服务端持有数据、设备用浏览器连它登录（真正的"多设备登录"，但要求长期在线的公网服务，且"数据只在你自己磁盘上"这条卖点失效）；② 服务端只做中继、按条目下发改动（多端体验最好，但服务端必须常驻并持有密文增量，磁盘格式大概率要动）；③ 设备之间局域网点对点直连、完全不经过任何云（零第三方，但出了家门就不同步，且要打开现在 DENY 的跨源与 Host 校验闸门）。选 ① 之外的第一条，是因为它改动半径最小：现有 `127.0.0.1` 监听、信封 v1 契约（ADR 0001）和身份档落盘形态都不用动。

## 后果

- **任何 provider 侧只可能看到密文**：云端拿不到明文，也就不承担任何解密职责；跨设备一致性只能在"整份密文快照"这一层解决，不能在服务端按条目合并。这条约束反过来砍掉了"服务端做合流/搜索/校验内容"的整类设计。
- **每台设备都得装包并各自解锁**：不存在"账号"这个概念被引入的理由。若后续决定给同步引入服务端账号体系，必须另立 ADR 并重新审视本条。
- **与"无云端账户"这句界面文案冲突**：`src/App.tsx:550` 首屏写着"无云端账户"。它现在需要被改成一个更精确的说法，而不是简单删掉——具体措辞要等同步术语敲定后一并落，本条不预先动界面文案与 README。
- **手机等无法跑本机服务的设备**：本条定稿时是空洞，现由 [ADR 0012](0012-carrier-object-storage-plus-readonly-worker.md)（只读代理 Worker）与 [ADR 0020](0020-read-only-phone-no-passphrase.md)（手机不设口令门槛）补上。要如实记下例外：**在只读端上，云端快照就是它唯一的数据来源**——"事实源在本地"这句对手机不成立，它没有本地库。此外 ADR 0012 引入的 Worker 是对本条"不养服务端"取向的折扣。
